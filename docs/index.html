An inventory, then an investigation

Read an SVG
structure report.

A path count is a starting point. Work through six small SVGs to connect the inspector’s JSON to the source, separate evidence from assumptions, and decide what to check next.

The boundary: this Python tool inventories XML. It does not render, trace, optimize or sanitize artwork. Counts cannot certify visual completeness, editability, security or suitability for cutting.

01 · Reproduce the evidence

Start with a known file.

Download the example bundle and extract it. Open a terminal in the extracted folder that contains svg_structure_inspector.py. Use a maintained Python release with Python 3.10+ syntax support; no third-party package or account is required.

Download the example bundle ZIP · 7.7 KiB · CLI, eight original fixtures and MIT license

python svg_structure_inspector.py fixtures/shapes-only.svg
python svg_structure_inspector.py fixtures/mixed.svg
python svg_structure_inspector.py fixtures/reuse.svg

If your Python command is python3, use that name instead. If the command cannot find a file, check your current folder and keep the bundle’s fixtures/ directory beside the script. The tool reads local files; it does not fetch the references inside them.

Each lesson links the complete source as inert text and the actual JSON result. Displayed JSON blocks are excerpts, not complete reports. The bundled fixtures and CLI come from source revision 2d675e3; the results were reproduced on 25 October 2026.

Your task: what does the report establish, what remains unknown, and which check would resolve that uncertainty?

external includes relative filenames; it does not mean “an internet request was made.” An svg hint does not mean “all vector content”: the referenced SVG may itself contain images. A misleading extension or media declaration can also mislead the hint.

Next check

Locate the referenced asset in a source you trust, verify its actual format, and inspect it separately. Treat unknown as a reason to investigate, not as a raster or vector verdict. The example’s deliberately unavailable URLs are not files you need to download to reproduce its report.

06 · namespaced.svg

A tag’s name includes its namespace.

The prefix s: maps to the SVG namespace in this source. The other: prefix maps to a different namespace. A comment also contains tag-looking text. Only parsed SVG elements belong in svg_element_counts.

Source excerpt · the root declares the two namespaces

<s:svg xmlns:s="http://www.w3.org/2000/svg"
       xmlns:other="urn:example:metadata">
  <!-- Comment text: <image/> <path/> -->
  <s:path d="M2 10 L8 16 L18 3" />
  <s:text>A &amp; B</s:text>
  <other:image>Not an SVG image element</other:image>
</s:svg>

Next check

Write down the unresolved dependency that matters to your task. For a missing visual effect, that may be a style or filter resource. For reusable geometry, it may be target expansion. A structure inventory helps choose that investigation; it does not complete it.

08 · Use the result within its limits

Know what a successful run means.

inspection: "structure_only" is the central qualification. The tool does not validate SVG path syntax, evaluate layout or CSS, expand reuse, decode embedded images, or load external resources. Its output does not echo input paths, IDs or reference values.

Input limits in version 0.1.0
BoundaryAccepted input
BytesAt most 1,048,576 bytes (1 MiB)
ElementsAt most 10,000 across all namespaces
NestingAt most 256 levels; the root counts as one
Encoding and rootUTF-8 XML, optional UTF-8 BOM, and svg in http://www.w3.org/2000/svg

DTD and custom entity declarations are rejected. Normal XML escapes and numeric character references are allowed. SVGZ, HTML and a root without the SVG namespace are unsupported inputs. An external .svgz filename can still receive an SVG type hint; that does not mean the inspector can open compressed SVGZ input.

A rejected input can be malformed or simply outside this tool’s supported boundary. Do not interpret every rejection as a universal declaration that the file is invalid SVG.

Exit codes and fields worth keeping straight

0 means an inventory was produced. 1 means input could not be read. 2 means rejected input or incorrect CLI usage. Inventory and input-error JSON go to stdout; incorrect CLI usage instead prints standard usage text to stderr. Help and version output are plain text.

image_references combines image and feImage, with one-based indexes in their document order. use_references has its own indexes. duplicate_id_count counts identifier names that occur more than once, not the number of extra elements.

Definitions and hidden elements are counted. The report does not decide whether an element is drawn. Keep Python and its XML parser updated; these limits do not make the tool a sanitizer.

Try the workflow on your own file

python svg_structure_inspector.py "your-file.svg"

Record one structural observation, one uncertainty and one next check. For example: “An image has a PNG filename hint; its bytes and visual contribution are unknown; inspect the trusted source asset and compare a copy with that object hidden.” Keep the original file unchanged while investigating.

When your starting file is a raster image

I maintain this inspector and pic2svg. If tracing is your next step, pic2svg offers free hosted SVG tracing; uploaded images are processed on its server. This offline inspector does not call that service. You can inspect a downloaded SVG with the same local workflow described above.
